# ENG-10573: prove framework support with a conformance kit

Branch `eng-10573`, stacked on `eng-10571`. Package `packages/witness`.

## Summary

- Adapters are now presets. A suite can override each capability: `report` (as before), `select`,
  the new `${WITNESS_SELECT}` placeholder, the new `list`, and the new `per_test_timeout_arg`.
- When a suite can't list its tests, witness uses the tests of its last complete report and names
  that source wherever it uses it.
- `witness check` prints one capability line per suite, with what each missing capability costs.
- The new conformance kit runs 12 real framework projects through 7 scenarios. Final local run:
  82 pass, 2 n.a., 0 fail.
- The kit found 15 Witness bugs; all are fixed. Tests went from 151 to 171, all passing.

## What changed

### Config (backward compatible; every new key is optional)

- `list = "<cmd>"` or `list = { cmd, format = "lines" | "report" | "adapter", report = "<glob>" }`
  (`"junit"` is accepted for `"report"`). The default format is `adapter` when the adapter has a
  list parser, else `lines`.
- `${WITNESS_SELECT}` (or `${WITNESS_SELECT:-default}`) in `cmd` marks where the runner's
  arguments go. Witness puts the report args, the per-test timeout and the selection there, so
  selection works in compound commands. Without the placeholder, witness appends at the end as
  before.
- `per_test_timeout_arg = "... {s} ..."` (or `{ms}`): the runner flag for adapters that have none.
- I did not add `kind` (ENG-10572 adds it).

### Engine

- `src/adapters.ts`: each adapter declares `selectArgs` (what the placeholder becomes), a native
  `list` spec (args, optional rewrite, and format: the adapter's parser, or a report written by a
  run that runs nothing), `plugins` (a cheap probe plus the error text that shows a plugin is
  missing), and `amend` (facts the console states and the report leaves out).
- New `src/listing.ts`:
  - one listing path for `plan check`, `check`, and the run's missing-report fallback;
  - the per-suite cache in `.witness/cache/tests/<suite>.json`, written after every full run whose
    report was readable and whose process exited on its own, keyed by adapter and folder;
  - `capabilities()` for the check line.
- `plan check` and `check` list with the suite's `env`. For `${svc.url}`, `plan check` uses the
  URLs `witness up` left running, else `http://127.0.0.1:9`.
- `plan check --json` has a new `listings` array (source, detail, ids).
- Reruns read the list's source:
  - ids from an old report that are gone now end as `other/missing`, not `failed`;
  - a partly readable report (a cut `go test -json` stream) keeps the tests it finished and reruns
    the rest;
  - when witness can't rerun, the suite-level row says why.
- Under `--select`, skipped rows for tests that weren't asked for are dropped. jest and vitest
  report every filtered-out test as skipped.
- A framework's own per-test timeout message makes a row `failed`/`timeout`. Covered: pytest-timeout,
  jest, mocha, Playwright, vitest, JUnit 5, PHPUnit and go panics.
- Failure messages are the first lines of the failure, without colours or stack frames.
  They used to be its first line only, which for jest, mocha and Playwright was a generic header.
- Readiness:
  - `localhost` is probed on 127.0.0.1 and on ::1;
  - a started service that answers only on ::1 is ready, and its URL becomes `http://[::1]:PORT`;
  - the port-held check also covers ::1.

### Kit (`packages/witness/conformance/`)

- `app/server.mjs`: the shared app. It serves `/health`, `/api/items`, `/api/items/:id` and an
  HTML page at `/`. `/api/hang` and `/hang` never answer.
- `projects/<framework>/`: 12 projects with pinned versions and lockfiles.
- `bin/in-docker`: runs a command in an image with the folder mounted at its own path. It forwards
  `WITNESS_*` variables and rewrites loopback URLs to `host.docker.internal`.
- `bin/break-report.mjs`: deletes or truncates the report a run wrote. It leaves listings, reruns
  and retries alone.
- `frameworks.ts`: the descriptors.
- `run.ts`: the runner. It picks a local or Docker toolchain, prepares dependencies, writes one
  config per scenario, checks the CTRF and `status.json`, prints the matrix and saves
  `.results/<time>.json`.

### Other files

- CI: new job `witness-conformance` in `.github/workflows/validate.yml`, one matrix entry per
  framework, using setup-node, setup-python, setup-java, setup-gradle, setup-go, setup-ruby,
  setup-php and setup-dotnet.
- Docs: `docs/witness/FRAMEWORKS.md` (support matrix, versions, known limits). The package README
  documents the new keys, the fallback, the kit, and per-test timeouts in the adapter table.
- Skills: one paragraph in `init` on reading the capability line. The plugin copy is regenerated.

## Bugs the kit found (all fixed)

| # | framework | bug | fix |
| --- | --- | --- | --- |
| 1 | all | listings (plan check, check, the missing-report fallback) ran without the suite's `env` | apply the suite env |
| 2 | all | `check` listed with the unsubstituted command, so `${svc.url}` reached bash | substitute with the live stack |
| 3 | pytest | the timeout regex expected `Timeout >3.0s`; pytest-timeout prints `Timeout (>3.0s)` | regex |
| 4 | jest, mocha, playwright | the CTRF message was a generic first line ("expect(received).toBe(expected)") | first lines of the failure |
| 5 | jest | after a timed-out test the open request kept jest alive, so the suite stalled for the full `stall_timeout` | `--forceExit` with the per-test timeout; the stall diagnosis quotes "did not exit" |
| 6 | mocha | the same, without `.mocharc` `exit` | `--exit` with the per-test timeout |
| 7 | vitest | `-t` matched nothing: vitest 5 joins titles with ` > `, and witness used spaces | either separator |
| 8 | vitest | `vitest list` leaves out skipped tests | list through a `-t` that matches nothing, read from the junit report |
| 9 | gradle | "FAILURE: Build failed with an exception" also appears when tests fail, so a missing report became `setup_failed` | match a failed `compile*` task |
| 10 | gradle | the same passing `--select` twice: the up-to-date test task wrote no report, so the run ended `error/missing` | the preset adds `--rerun` (Gradle 7.6+) |
| 11 | rspec | the plugin check matched the echoed `$ cmd` line, so every missing report read as "rspec_junit_formatter missing" | ignore echoed commands; match the real LoadError |
| 12 | go | the `-timeout` panic is in the test's own output, and the parser looked at package output only | look at both: `failed`/`timeout` |
| 13 | go | a cut `-json` stream counted as complete, and tests after the cut silently disappeared | partial report: rerun the rest |
| 14 | phpunit | a test aborted at its time limit is "risky" and a pass in JUnit (a false pass); the time limit also needs `--enforce-time-limit` | `amend` from the console; the preset adds `--enforce-time-limit` |
| 15 | dotnet VSTest | `--blame-hang-timeout` kills the host, and the hung test vanished from the results | `amend` adds it from "The test running when the crash occurred" |

The last-report cache was first keyed on the suite command, so any wrapper invalidated it. It is
now keyed by adapter and folder; stale ids are handled by the `other/missing` rule above.

## Scope changes

- Added `amend`, an adapter hook that corrects a report from the console. PHPUnit and VSTest needed
  it; without it, a timed-out test was a pass or vanished.
- Added partly readable reports: keep the readable tests, rerun the rest. The contract covers only
  fully unreadable reports.
- The jest, mocha, gradle and phpunit presets add flags: `--forceExit`, `--exit`, `--rerun` and
  `--enforce-time-limit`.
- The kit's `select` scenario also reruns the same selection twice. That check is how bug #10 was
  found.
- Docker fallbacks were run for Maven, Gradle and RSpec only. pytest, go, phpunit and dotnet ran on
  local toolchains.
- The CI job is written but has not run yet: nothing was pushed, as instructed.

## Open questions

1. Should the cache key also include the command? Today a cached list survives command edits. Ids
   that no longer exist end as `other/missing` in a run that is already `error`.
2. Should go output with no JSON events be `report_missing`? It stays `report_unreadable` because an
   existing test pins that behaviour.
3. MSTest `Assert.Inconclusive` reached the TRX as not executed (skipped) in this setup. The TRX
   parser maps an `Inconclusive` outcome to `other`, which counts as error. Should it be skipped, as
   VSTest's console shows it?
4. Is `--rerun` on every Gradle run acceptable? Projects on Gradle older than 7.6 fail with "Unknown
   command-line option". Their fix is to put `--rerun-tasks` or `cleanTest` in `cmd`, which turns the
   automatic flag off.
5. The CI kit job installs Chromium with `--with-deps` and resolves Maven and NuGet packages on every
   run. Should the job cache dependencies, or run only when `packages/witness/**` changes?
