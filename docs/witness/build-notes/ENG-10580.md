# ENG-10580: render skills per profile (standalone, morph)

Branch `eng-10580`, stacked on `eng-10574`. Package `packages/witness`.

## Summary

- Skill sources now hold `<!-- if morph -->`, `<!-- if standalone -->`, `<!-- else -->` and
  `<!-- endif -->` blocks. Witness renders them per profile, and rendered output has no markers left.
- `witness skills install --profile standalone|morph` (default standalone) and
  `witness skills path --profile ...` render. They no longer copy or print the raw sources.
- `--link` works only with standalone. It links to the rendered copies in witness's cache.
- `npm run build:plugin` renders the standalone profile. `npm run check:skills` checks every profile.
- The morph-only procedure that morph's subagent prompt used to override now lives in `morph`
  blocks. The user-only steps live in `standalone` blocks.
- Morph side deferred: `scripts/refresh_witness.sh` needs `--profile morph`, and the prompt
  lines listed below can then go.

## Syntax

```markdown
<!-- if morph -->
morph only
<!-- else -->
standalone only
<!-- endif -->
```

- Each marker sits alone on its line. Leading spaces are allowed, so a block can sit inside a list item.
- `else` is optional, and blocks do not nest.
- These are build errors, reported as `file:line: message`:
  - an unknown profile;
  - a marker sharing its line with text;
  - a marker in the frontmatter;
  - `else` or `endif` without `if`;
  - a second `else`;
  - a nested `if`;
  - an unclosed `if`, reported at the line of the `if`.
- Rendering drops every marker line and the lines of the other profile. Where a dropped block
  would leave two blank lines in a row, it drops one. A file with no markers renders byte for byte.
- Frontmatter is shared, so `witness skills list` keeps reading the sources.

## CLI

| command | what it does |
| --- | --- |
| `witness skills install --dir <d> [--profile p] [--prefix witness-]` | Writes the rendered skills as `<prefix><name>` and renames `name:` in the frontmatter. Keeps the `.installed-by-witness` marker and the foreign-folder refusal. |
| `witness skills install --dir <d> --link` | Renders standalone into the cache, then links each skill there under its own name. Exits 64 with any other profile. |
| `witness skills path [--profile p] [--json]` | Renders into `$XDG_CACHE_HOME/witness/skills/<profile>` (default `~/.cache`) and prints that folder. `--json` adds `profile` and `source`. |

An unknown `--profile` exits with 64.

**Why `--link` refuses morph.** Morph vendors copies into its own templates, so a link into a
developer's cache would point nowhere inside a sandbox. Linking the raw sources is no longer
possible either, because the agent would see the markers. The link targets the rendered standalone
copies. The cost: a link picks up source edits only after witness renders again (`skills path` or
`install --link`), not on every save.

**No `skills render` command.** Morph's script already calls
`skills install --dir "$TMP" --prefix witness-`, then deletes the `.installed-by-witness` markers.
It only needs `--profile morph` added. A second command would duplicate `install`.

## What moved where

Morph blocks:

- `test-change` rules:
  - Nobody answers questions. Wherever a skill says to ask or tell the user, the agent records a
    blocker for the final report (what is needed, cause and evidence line, what was tried) and
    goes on with what does not depend on it. This also covers questions that the other ticket
    adds to `init`.
  - The rendered config: morph re-renders it before each run until it is edited, then keeps the
    agent's version. Edit it only to fix what `check` or a diagnosis shows is wrong.
  - Temporary files go in `$MCODE_DIR/scratch/`.
  - Commit the tests, `plan.yaml` and `witness.toml`.
- `test-change` step 1: use `node "$WITNESS"` when `witness` is not on PATH; otherwise stop with a
  blocker.
- `test-change` report: blockers with the diagnosis lines.
- `init`: keep a config that morph rendered and start at step 3. Morph supplies the secrets, so
  list their names in `[env] required` and never write a value into a file. Commit the config
  with the tests.
- `plan` step 1: expectations come from the milestone spec, then the project spec. `source` names
  the spec, and `expect` comes from the spec, not from the code.
- `triage`:
  - `missing_env`: a setting that is not secret may go in the service's `env`. A missing secret
    is a blocker naming the variable.
  - Step 5 becomes a blocker for the final report.
- `verify` step 1: when the instructions ask for parity, every full run is `--against origin`;
  otherwise there is no `--against`. Morph records the last run, so it must be full, never
  `--select`.

Standalone blocks:

- `test-change` step 1 and the report: tell the user.
- `init`: secrets go in `.witness/.env`. Commit the config only if the user wants it in the repo.
- `plan` step 1: the user's request, the PR, the issue.
- `triage`: `missing_env` goes in `.witness/.env`, or ask. Step 5 tells the user.

Shared edits made to fit the budget:

- `verify`'s report names the parity counts and asks for both statuses on each `differs` test.
  This used to be in morph's prompt.
- `test-change` "Long commands" first bullet and `init` step 3 first paragraph: shorter wording,
  same content.
- `write` is unchanged.
