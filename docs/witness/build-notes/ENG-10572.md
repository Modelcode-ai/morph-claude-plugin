# ENG-10572: Witness runs functional tests only

Branch `eng-10572`, stacked on `eng-10571`.

## TL;DR

- Every `[[suite]]` must now declare `kind = "api" | "ui"`. A config without it is rejected with a message that names both values and says unit and integration tests don't belong in Witness.
- `witness init` proposes a suite only for test projects whose tests drive the app. It lists every excluded project with a reason. For mixed projects it proposes a filtered command, or marks the project "needs a filter".
- On eShopOnWeb, `init` proposes `FunctionalTests` (api), `PublicApiIntegrationTests` (api) and `EndToEndTests` (ui). It excludes `UnitTests`, `IntegrationTests` and `AppHostTests`.
- One deviation from the expected result: `PublicApiIntegrationTests` gets a filter that skips `DependencyTests`, a package-graph check that never calls the API. The suite runs 143 of the 144 tests (checked with SDK 11 in Docker).
- `witness check` warns when a suite's test files don't drive the app. `status.json`, CTRF and `witness report` now carry `kind` and the services each suite used.

## What changed

**Config (`src/config.ts`).**
- Added `suite.kind`, which is required and must be `"api"` or `"ui"`.
- An error looks like this: `suite.unit.kind: is required: set kind = "api" for tests that drive the app over HTTP ..., or kind = "ui" ... Unit and integration tests don't belong in Witness: the project's own build and test scripts run them`.
- The edit is local: one key, one field, three lines of parsing.

**Classifier (`src/functional.ts`, new).**
- It reads each file with lint's `mask()` and `findTests()`, then records signals from module imports, calls on masked code, and string literals checked against the raw text.
- Signal types:
  - in-process app hosts: `WebApplicationFactory`, `TestServer`, FastAPI/Starlette `TestClient`, httpx `ASGITransport`, Flask `test_client`, the Django/DRF client, supertest, `MockMvc` and `@SpringBootTest`, Rails request specs, Laravel `$this->getJson`, Symfony `WebTestCase`, Go `httptest.NewServer` and `ServeHTTP`;
  - HTTP calls;
  - base URLs (environment variables named `*URL`/`*HOST`, `localhost:<port>`, `baseURL`);
  - browser drivers: Playwright `page.*`, Cypress, Selenium, Capybara, Dusk/Panther, chromedp;
  - tests that start the app themselves (`ProcessStartInfo`, Playwright `webServer`);
  - database access and HTTP mocks (`responses`, `nock`, `msw`, WireMock and similar).
- A test file counts as functional when:
  - it drives a browser (`ui`);
  - or it makes HTTP calls, they aren't mocked, and the project hosts the app or names a URL (`api`).
- Two narrower rules:
  - A URL in a test file counts only for that file. In eShop's `UnitTests`, a `https://localhost:5001` string is test data.
  - In Python, `client.get(URL)` with a non-literal argument counts only in files that create the `TestClient` themselves.
- Each project gets one verdict: functional, excluded, or mixed.
  - An excluded project's reason starts with `unit (...)`, or with `integration (database access; ...)` when half or more of its test files touch a database.
  - Notes such as the Aspire app-model case are added to the reason.
- Filters for mixed projects, tried in this order:
  1. one folder;
  2. a tag shared by all functional files and by no others (pytest marks, xunit/NUnit/MSTest categories, JUnit `@Tag`, rspec `type:`, phpunit groups);
  3. skipping up to 5 non-functional files when functional files outnumber them at least two to one;
  4. up to 6 folders.
- The filter syntax depends on the adapter. For dotnet it is `--filter` with `FullyQualifiedName` (VSTest, MSTest/NUnit on MTP) or `--filter-namespace`/`--filter-not-class`/`--filter-trait` (xunit v3 on MTP).
- When no filter fits, the project goes on the "needs a filter" list.

**`witness init` (`src/init.ts`).**
- Projects: each test csproj, pytest root, package.json (jest/vitest/mocha/cypress), each Playwright config, the shallowest Maven/Gradle build, go module, rspec Gemfile and `phpunit.xml`.
- Playwright:
  - One project per `playwright*.config.*` file.
  - It honors a config-wide `testDir`, and a `testIgnore`/`testMatch` regex given literally or as a `const` in the same file.
  - It ignores keys set per project and sibling configs.
  - A config with no spec files under its `testDir` is excluded.
- The generated TOML carries:
  - `kind` on every suite;
  - `service = []` when the tests start the app themselves;
  - a commented-out suite for each "needs a filter" project, listing its functional files;
  - a `# Not proposed:` comment block with each excluded project and its reason.
- `--json` adds `excluded` and `needsFilter`.

**`witness check` (`src/commands.ts`).**
- Warns at the config stage without failing.
- It finds the folders and files named in the suite's command (a csproj's folder, or pytest/jest paths) and falls back to `cwd`.
- It collects test files with lint's `expandArgs` and classifies them.
- It warns when no test file drives the app. It also warns when some files don't and the command has no filter flag.
- Each warning names the suite, the number of files scanned, the folders, up to three sample files, and the fix.
- Generic suites whose command names no path are skipped.
- `--json` adds `warnings`.

**Run output.**
- Each suite in `status.json` has `kind` and `services`. `services` lists the services Witness started for the suite, and is empty when the tests start the app themselves.
- CTRF `tests[].extra.witness.kind`.
- `witness report` adds Kind and App columns, plus one line explaining "in the tests". `witness status` shows the kind.

**Skills.**
- `init`: functional suites only; what the excluded and "needs a filter" lists mean; the `kind` and `service = []` keys.
- `plan`: items are behaviours visible from outside the app through its API or UI.
- `write`: write functional tests only.
  - Prefer tests that call the app Witness started.
  - How URLs reach suites today: every suite gets `WITNESS_<SERVICE>_URL` for each running service (`src/stack.ts` `serviceUrlEnv`, passed in `src/suite.ts`), and `${<svc>.url}` works in a suite's `cmd` and `env`.
  - Why it matters: tests that start their own copy of the app test the same code twice under `--against` with an origin service.
- `test-change`: states the rule.
- Regenerated into `plugins/morph/skills/witness-*`.

**Example.** `examples/eshoponweb.toml`:
- `functional` (api), `publicapi` (api, with the `DependencyTests` filter) and `e2e` (ui), all `service = []`;
- dropped `unit`, `integration` and the curl `smoke-http` suite.

**Fixtures.** `testdata/functional/<stack>/{unit,functional,mixed}` for dotnet, pytest, jest, vitest, mocha, playwright, junit-maven, junit-gradle, go, rspec and phpunit, plus `pytest/mixed-flat` for "needs a filter".

**Not touched.** `packages/witness/eval/**` (ENG-10574) and `src/adapters.ts` (ENG-10573).

### morph (pytest)

Proposed nothing. One project needs a filter: `61 of 1224 test files drive the app, mixed with 1163 that don't, and no folder, category or tag separates them`.

- The 61 files use FastAPI `TestClient` or httpx `ASGITransport` (for example `tests/unit/test_task_api.py` and `tests/unit/admin/test_admin_api.py`). They sit in `tests/unit/**`, plus 4 in `tests/integration/**`.
- I compared the 61 against every non-conftest file that mentions `TestClient`/`ASGITransport`. The only differences are a helper module (`_error_wire.py`, no tests) and `test_build_budget_accounting.py`, which matches only through a class named `TestClientError...`.

My judgement: the verdict is right. These files fit the user's definition (`TestClient`), but nothing separates them from 1163 unit test files. Many of them mount a single router with an `AsyncMock` session, which is closer to a handler unit test. To run them under Witness, morph needs a marker or a folder.

Two false positives found on these runs are fixed and covered by tests:
- A jest test that starts a fake upstream with `http.createServer(...).listen(0)` counted as hosting the app. The rule now needs `app.listen` or `createServer(app)`.
- A sibling Playwright config under `e2e/` leaked its `webServer` into the default config's project.

## Scope changes

- **Skip filter.** A mixed project can be filtered by skipping a few non-functional files, not only by folder, category or trait. Without it, eShop's `PublicApiIntegrationTests` would have been "needs a filter" because of one file.
- **`kind` is a breaking change.**
  - Every existing config without `kind` is now rejected.
  - This includes the configs under `packages/witness/eval/**`, which I didn't touch (ENG-10574).
  - It also includes morph's ENG-10543 renderer, which emits a generic suite without `kind` from the lifecycle `test` command. Morph breaks when it next refreshes the vendored bundle.
- **Cypress.** Proposed as a `generic` suite with a JUnit reporter into `$WITNESS_REPORT_DIR`, kind `ui`. There is no Cypress adapter.
- **One project per Playwright config.** Before, there was one Playwright suite per package. A config with no spec files is now excluded instead of proposed.
- **Status field.** `services` is a list (empty means the tests host the app); the brief called it `service`. `check --json` gains `warnings`; `init --json` gains `excluded` and `needsFilter`.
- **Mixed kinds.** A suite that mixes API and browser tests gets `kind = "ui"`.

## Open questions

1. **eShop `publicapi`: 143 or 144 tests?** `DependencyTests` checks the package graph. By the definition it isn't functional, so the example and `init` skip it. If you want all 144, drop the filter; `check` will then warn.
2. **None of eShop's three suites uses the managed `web` service.**
   - FunctionalTests and PublicApi host the app in-process. EndToEndTests starts `dotnet run` on `https://localhost:5001` itself.
   - So `witness run` never boots `web`. Its `/home_page_health_check` ready check runs only in `witness check`, and the dropped curl smoke suite isn't replaced in `run`.
   - `--against` with an origin service would test the same code twice. Worktree `--against` still compares the two refs.
   - The fix would be in eShop, not Witness: let `BrowserFixture` take its base URL from `WITNESS_WEB_URL`. Should ENG-10574 do that?
3. **morph's renderer (ENG-10543).** It must emit `kind` and should stop turning the lifecycle `test` command into a suite. That command is usually the unit test run, which this issue rules out. Separate issue?
4. **morph's own tests.** Do router tests with mocked sessions count as functional for morph? If yes, add a marker (for example `@pytest.mark.api`); `init` then proposes `python -m pytest -m api`.
5. **Classifier limits.**
   - Go: `httptest.NewServer(http.HandlerFunc(...))` is treated as a fake dependency, and any `.ServeHTTP` as the real router.
   - Playwright `testMatch` imported from another file is not resolved.
   - All of this is static, so a wrong guess is possible. `init` says why it decided, and the init skill tells the agent to override and report.
6. **Plugin version.** `plugins/morph` stays at 0.7.0, which is unreleased in this stack. Bump it?
